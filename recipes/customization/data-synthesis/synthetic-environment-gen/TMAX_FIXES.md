# Fixes we patched on TMax locally

Our corpus was generated with TMax at `6d3d606c` plus a handful of small changes in a patched copy; the ones that matter for reproducing the run are below. The recipe runs stock TMax, and the numbers in the README come from the patched run. Each change is worth carrying upstream; the exact prompt text is in `config/prompt_rules.md`.

1. **Prompt rules** (`rl_data/generator/{task_template_gen,initial_state_test_gen,completion_test_gen,apptainer_def_gen}.py`, the `SYSTEM_MSG` and `build_system_prompt` strings). Append the four blocks of `config/prompt_rules.md`: a preamble that each stage answers with the requested artifact only, task rules that keep every environment runnable in a plain container (no Docker, systemd, firewall or root-only work), an initial-test rule (no running-process assertions, since the image is tested right after build), and verifier rules (test behavior, never the text of agent-written source; normalise whitespace; no privileged tooling). The verifier rules are what make a verifier accept any correct solution rather than the one its author had in mind.
2. **Re-sample unparsable outputs** in stages 2 and 3 (`generate_tasks.py`, the `generate_initial_tests_batch` and `generate_final_tests_batch` calls): a generation call whose output did not parse is asked again, up to two more times. Stock TMax drops the task.
3. **Static verifier filter** on the stage-3 output: reject a verifier that calls `docker|systemctl|systemd|journalctl|ufw|nft|nftables|iptables|modprobe|sysctl|mount`, that reads a source file and asserts a substring of it, or that compares a string of 20 or more characters with `==` without `.strip()` or `split()`. Regenerate once with the reason appended to the task description, then drop.
4. **Readable build errors for the repair rounds.** TMax feeds the last 500 characters of the build output back to the model; with Docker's buildkit that is progress chatter, so keep the last 2,500 characters with the progress lines stripped.
5. **Docker instead of Apptainer in stage 5** (`apptainer_def_gen.build_and_test`): translate the definition the way `convert_to_harbor.py` does, build, run the initial-state test in the image with `--network=none --memory 4g`, remove the image. Stock TMax with Apptainer gives the same result.
6. **Harbor task limits** after conversion: `solve.sh` applies `config/task_overrides.toml` at staging time, so stock TMax is fine here.
7. **Restore `%environment` in the Harbor Dockerfile.** The converter drops the definition's exports and sets no working directory; add them as `ENV` lines and `WORKDIR /home/user`, or tasks that put a tool on `PATH` fail their verifier through no fault of the agent.
8. **Text-only fixtures:** drop the `image`, `audio` and `video` fixture kinds from `task_template_gen._FIXTURE_NEW` when the student model is text-only.
